Máquina de estados — Paso de Auditoría (AuditStep)

Transiciones de estado, validaciones de negocio, roles autorizados y sincronización automática de ProcStatus

Validaciones de negocio

SUBMITTED requiere: performedByName (nombre auditor ejecutor) y datePerformed (fecha de ejecución). Si falta alguno el API lanza BadRequestException.
REVIEWED → CLEARED solo lo puede hacer un usuario con rol Supervisor o superior.
CLEARED → APPROVED requiere rol Socio / Director. Es el paso de control de calidad final.

Estados terminales vs. activos

Terminales: CLEARED, APPROVED — un paso en este estado cuenta como "completado" para el cálculo de ProcStatus.
Activos: IN_PROGRESS, SUBMITTED, REVIEWED — mantienen ProcStatus en IN_PROGRESS.
DRAFT: estado inicial neutro. Si TODOS los steps están en DRAFT → ProcStatus = PENDING.

Evidencia en cada step

Cada AuditStep puede tener N archivos StepEvidence adjuntos (PDF, Excel, imagen).
Upload sube a Supabase Storage bucket audit-files, path procedures/steps/{stepId}/.
Delete elimina de Storage y de la BD de forma atómica. La evidencia acompaña el step en cualquier estado.
