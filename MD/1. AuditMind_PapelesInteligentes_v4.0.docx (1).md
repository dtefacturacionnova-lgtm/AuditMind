## **1.1 Deloitte Omnia — Working Papers Vinculados**

Deloitte fue el primero en separar los papeles de trabajo en capas: documentos adjuntos (PDF, Excel, Word) y secciones estructuradas nativas dentro de la plataforma. Las secciones nativas son campos de datos tipados que el sistema entiende y puede propagar. Un riesgo identificado en la sección de Evaluacion de Riesgo Inherente de un papel de planificacion aparece automaticamente como fila pre-llenada en la Matriz de Riesgo, que a su vez alimenta el Programa de Auditoria con los procedimientos sugeridos para ese riesgo.

|  Capas del modelo Deloitte Capa 1 — Documentos adjuntos: PDF, Excel, Word, imagenes, audios, videos — sin logica de negocio Capa 2 — Secciones estructuradas: campos tipados (texto, numero, lista, matriz) que el sistema entiende y propaga Capa 3 — Papeles maestros: papeles que consolidan datos de multiples secciones de otros papeles — el Memo de Planificacion es el ejemplo canonico Capa 4 — Papeles vivos: papeles que se actualizan en tiempo real cuando cambia cualquiera de sus fuentes — el Programa de Auditoria actualizado cuando se modifica la evaluacion de riesgo  |  |  Lo clave de KPMG Clara Workflow Clara tiene 5 componentes interconectados: Data, Workflows, Learning, Knowledge y Methodology — ningun componente trabaja aislado Cuando el auditor evalua un riesgo, Clara lo conecta automaticamente con el conocimiento de la industria del cliente y los procedimientos metodologicos de KPMG AuditBoard Sync mantiene frameworks, riesgos y auditorias enlazados — al actualizar un control se actualiza en TODAS las instancias donde aparece EY Canvas: segregacion de datos por cliente con reutilizacion de programas de auditoria entre proyectos similares  |

## **1.2 El Patron Comun — Lo que Todos Hacen**

Tras analizar los cuatro sistemas, el patron es consistente y se puede reproducir con el stack tecnologico de AuditMind:

| Patron | Descripcion | Implementacion en el Sistema |
| :---- | :---- | :---- |
| **Campos tipados vs. texto libre** | No todo es un campo de texto. Un riesgo tiene campos especificos (nombre, probabilidad, impacto, tipo) que el sistema puede leer y propagar | Modelo de datos Prisma con campos especificos por tipo de seccion, no JSON generico |
| **Referencias cruzadas** | Un campo en el papel A puede referenciar un registro del papel B. Cambiar B actualiza A automaticamente | Foreign keys \+ event bus (NestJS) que emite evento cuando el registro fuente cambia |
| **Papeles generadores y papeles receptores** | Algunos papeles son fuente de datos (se llenan a mano). Otros son destino (se llenan automaticamente con datos de los generadores) | Separacion de PT en tipos: SOURCE y DERIVED — los DERIVED nunca se editan directamente |
| **Consolidacion con IA** | Cuando los datos fuente estan completos, la IA genera la narrativa del papel maestro basandose en los datos estructurados | LLM Router invocado por el Agente Scriptorium con el contexto de todos los datos fuente |
| **Actualizacion en cascada** | Si un dato fuente cambia despues de que el papel maestro fue generado, el sistema marca el papel como Desactualizado y ofrece regenerar | Event-driven architecture: cambio en fuente → evento → invalidacion del papel dependiente |

| 📄  LOS 4 TIPOS DE PAPELES DE TRABAJO EN AUDITMind *Arquitectura de la red de conocimiento del proyecto* |
| :---- |

|  Tipo 1 — PT ESTANDAR El papel de trabajo tradicional. Contiene documentos adjuntos (PDF, Word, Excel, PPT, imagenes, audios, videos) y un area de narrativa libre del auditor. No tiene logica de propagacion — es evidencia pura. PDF, Word, Excel, PowerPoint adjuntos sin limite de archivos Imagenes, capturas de pantalla y fotos desde campo Audios y grabaciones de entrevistas Area de narrativa libre con formato rico Tick marks aplicables a cualquier campo Sin propagacion activa — es un receptor final  |  |  Tipo 2 — PT INTELIGENTE El corazon del sistema. Tiene secciones estructuradas con campos tipados que el sistema entiende. Cuando el auditor llena una seccion, los datos quedan disponibles para ser consumidos por otros papeles. Secciones predefinidas con campos tipados Cada campo tiene un ID unico que otros papeles pueden referenciar Asistencia de IA seccion por seccion — no solo al final Genera eventos cuando sus datos cambian Puede recibir datos de otros PT Inteligentes Combinado con archivos adjuntos cuando se necesita  |
| :---- | :---- | :---- |

|  Tipo 3 — PT MAESTRO El papel que consolida. Lee datos de multiples PT Inteligentes y los consolida en un documento cohesivo. El Memorando de Planificacion y el Programa de Auditoria son PT Maestros. El auditor revisa y aprueba — no escribe desde cero. Mapa de fuentes: declara que campos lee de que papeles Motor de consolidacion: el Agente Scriptorium genera la narrativa con los datos Estado: Borrador / Actualizado / Desactualizado Regeneracion selectiva: regenera solo las secciones cuya fuente cambio Version history: guarda cada generacion anterior Requiere aprobacion del supervisor antes del cierre  |  |  Tipo 4 — PT VIVO (Dashboard) El papel de seguimiento en tiempo real. Se actualiza automaticamente cada vez que algun dato relevante cambia en el proyecto. No requiere accion del auditor — siempre esta al dia. Actualización en tiempo real via WebSockets No tiene version history — siempre muestra el estado actual No requiere aprobacion — es informacion de gestion Ejemplos: Resumen del Proyecto, Estado de Solicitudes PBC, KPIs del Encargo Puede exportarse a PDF como fotografia del estado en un momento dado Visible para el supervisor y el CAE sin intervenir en el flujo  |

| 🕸️  EL GRAFO DE CONOCIMIENTO DEL PROYECTO *Como los datos fluyen entre papeles automaticamente* |
| :---- |

Cada proyecto de auditoria es un grafo dirigido. Los nodos son los papeles de trabajo. Los arcos son flujos de datos. Cuando un dato cambia en un nodo fuente, el evento se propaga por los arcos a todos los nodos que dependen de ese dato.

## **FASE A — PLANIFICACION**

|  PT-A1 Entendimiento del Negocio y Entorno *Captura el conocimiento del contexto de la entidad auditada que el sistema necesita para personalizar todos los demas papeles* PT INTELIGENTE 📝 Secciones del Papel: S1. Datos generales de la entidad (nombre, sector, tamano, estructura) S2. Descripcion del negocio y actividades principales S3. Entorno regulatorio aplicable (leyes, normas, reguladores) S4. Sistemas de informacion y ERPs utilizados S5. Estructura organizacional y areas clave S6. Cambios significativos en el periodo S7. Resultados de auditorias anteriores (importado automaticamente del historico) S8. Factores externos de riesgo (economicos, sectoriales, competitivos) 🤖 Asistencia de IA: Sugiere el sector y regulacion aplicable basandose en la descripcion del negocio Auto-completa cambios del periodo conectando con el historico de auditorias anteriores en la plataforma El Agente Cassandra agrega factores de riesgo externos del sector en tiempo real Sugiere sistemas ERP tipicos del sector si el auditor no los especifica ⬇️  Recibe datos de: Datos del proyecto (nombre, fechas, equipo) Historico de auditorias anteriores (automatico) ⬆️  Alimenta datos a: PT-MEMO (secciones 1, 2, 3\) PT-A2 (contexto para evaluacion de RI) PT-PROG (seleccion de CAATs por sector) Base RAG del proyecto (activa los skills relevantes)  |
| ----- |

|  PT-A2 Evaluacion del Riesgo Inherente (RI) *Matriz de evaluacion del riesgo inherente por area/ciclo/cuenta significativa — la base de todo el enfoque de auditoria* PT INTELIGENTE 📝 Secciones del Papel: S1. Lista de areas y ciclos auditados (importada del universo de auditoria) S2. Identificacion de saldos significativos (vs. materialidad calculada en PT-A4) S3. Evaluacion de RI por area: factores cualitativos (complejidad, estimaciones, cambios) S4. Score de RI: Alto (0.7-1.0) / Moderado (0.3-0.7) / Bajo (0.05-0.3) S5. Identificacion de riesgos especificos de error material (fraude o error) S6. Riesgos significativos que requieren procedimientos especificos (NIA 315\) S7. Evaluacion de riesgo de fraude segun indicadores del triangulo ACFE S8. Conclusión por area: enfoque sugerido (controles vs. sustantivo) 🤖 Asistencia de IA: El Agente Minerva sugiere los riesgos tipicos del sector para cada area basandose en el RAG de industria El Agente Sherlock resalta areas con indicadores de fraude segun el triangulo ACFE Score de RI calculado automaticamente basandose en los factores marcados por el auditor Resalta areas con cambios significativos que el auditor debe evaluar con mayor profundidad ⬇️  Recibe datos de: PT-A1 (entendimiento del negocio) PT-A4 (materialidad para identificar saldos significativos) Universo de auditoria (areas auditables del proyecto) ⬆️  Alimenta datos a: PT-A3 (RI como input del modelo de riesgo) PT-MRCI (filas de riesgos identificados) PT-MEMO (seccion evaluacion de riesgo) Programa (priorizacion de procedimientos) Materialidad (areas de alto riesgo ponderan la base)  |
| ----- |

|  PT-A3 Evaluacion de Controles y Riesgo de Control (RC) *Evaluacion del diseno e implementacion de controles clave — determina el Riesgo de Control y el enfoque de las pruebas sustantivas* PT INTELIGENTE 📝 Secciones del Papel: S1. Controles clave identificados por area (vinculados a los riesgos de PT-A2) S2. Evaluacion del diseno del control: Adecuado / Inadecuado / No existe S3. Prueba de implementacion: como se verifico que el control opera S4. Resultado de prueba de efectividad operativa (si se decide probar) S5. Nivel de RC resultante: Alto / Moderado / Bajo por area S6. CALCULO AUTOMATICO: RA objetivo (5%) / (RI × RC) \= RD requerido S7. Implicacion del RD en el enfoque: Dependencia de controles / Sustantivo / Combinado S8. Deficiencias de control identificadas — vinculacion directa a Hallazgos 🤖 Asistencia de IA: El Agente Atlas sugiere controles esperados para cada area segun COSO/COBIT aplicable El sistema calcula automaticamente el Triangulo de Riesgo (RI × RC \= RA/RD) al completar las evaluaciones Cuando RC es Alto, el sistema alerta que se requieren mas pruebas sustantivas y actualiza el Programa Deficiencias identificadas se convierten en borrador de hallazgo con un click ⬇️  Recibe datos de: PT-A2 (riesgos inherentes identificados) RAG normativo (controles esperados segun COSO, COBIT, NIA) ⬆️  Alimenta datos a: PT-MRCI (columnas de controles) PT-MEMO (seccion enfoque de auditoria) Programa (determina tipo y extensión de procedimientos) Hallazgos (deficiencias de control pre-cargadas)  |
| ----- |

|  PT-A4 Calculo de Materialidad (NIA 320\) *Determina los umbrales de materialidad que guian todo el trabajo de auditoria — base para tamanos de muestra y clasificacion de hallazgos* PT INTELIGENTE 📝 Secciones del Papel: S1. Base de calculo seleccionada: utilidad antes de impuestos / ingresos / activos totales / gastos S2. Porcentaje aplicado segun tipo de entidad y sector (configurable por el auditor) S3. CALCULO AUTOMATICO: Materialidad Global (MG) \= Base × Porcentaje S4. CALCULO AUTOMATICO: Materialidad de Ejecucion (ME) \= MG × 75% S5. CALCULO AUTOMATICO: Umbral de Acumulacion de Errores (UAE) \= MG × 50% S6. Justificacion del nivel de materialidad seleccionado (narrativa del auditor) S7. Cambios vs. periodo anterior y su justificacion 🤖 Asistencia de IA: El sistema sugiere el porcentaje de materialidad tipico para el sector del cliente basandose en el RAG Los tres niveles (MG, ME, UAE) se calculan instantaneamente al ingresar la base y el porcentaje Cuando se cierra el papel, los calculos se propagan automaticamente a todos los papeles que los necesitan ⬇️  Recibe datos de: Estados financieros del cliente (datos de la base de calculo) ⬆️  Alimenta datos a: PT-MEMO (seccion materialidad) Programa (tamanos de muestra calculados sobre ME) Hallazgos (impacto vs. MG para clasificacion material/no material) PT-A2 (saldos significativos identificados sobre umbral ME)  |
| ----- |

|  PT-MEMO Memorando de Planificacion *El papel maestro de planificacion — consolida automaticamente todos los datos de PT-A1 a PT-A4 en un documento narrativo profesional* PT MAESTRO 📝 Secciones del Papel: S1. ENCABEZADO (auto): Cliente, tipo de encargo, periodo, equipo, fechas — del proyecto S2. ENTENDIMIENTO (auto de PT-A1): Descripcion del negocio, sector, sistemas, regulacion S3. EVALUACION DE RIESGO (auto de PT-A2): Riesgos identificados por area con nivel de RI S4. MATERIALIDAD (auto de PT-A4): Calculos y justificacion S5. ENFOQUE DE AUDITORIA (auto de PT-A3): Tipo de enfoque por area segun RI × RC × RD S6. EQUIPO Y PRESUPUESTO DE HORAS (auto del proyecto): Asignaciones y horas estimadas S7. CRONOGRAMA (auto del proyecto): Fechas de cada fase S8. CONCLUSION DE PLANIFICACION (IA \+ auditor): Resumen narrativo profesional S9. SECCION EDITABLE: El auditor puede agregar consideraciones adicionales S10. FIRMA DIGITAL: Preparado por, Revisado por, Aprobado por (CAE/Socio) 🤖 Asistencia de IA: El Agente Scriptorium genera el borrador completo al ejecutar la consolidacion — el auditor recibe un documento 90% listo Cada seccion auto-generada tiene un indicador de fuente: el auditor puede ver de donde vino cada dato Si cualquier fuente cambia despues de la generacion, el sistema marca las secciones afectadas como Desactualizadas El auditor puede regenerar seccion por seccion o el documento completo con un click ⬇️  Recibe datos de: PT-A1 (entendimiento) PT-A2 (riesgos) PT-A3 (enfoque) PT-A4 (materialidad) Datos del proyecto (equipo, fechas, alcance) ⬆️  Alimenta datos a: Programa de Auditoria (primer documento de ejecucion) Portal del auditado (adjunto para lectura del auditado) Informe Final (seccion Alcance del informe lee del Memo)  |
| ----- |

|  PT-MRCI Matriz de Riesgo, Control e Impacto *La matriz central que enlaza riesgos, controles, brechas y procedimientos — base del programa de auditoria* PT MAESTRO 📝 Secciones del Papel: Columnas: Proceso/Area | Objetivo de Control | Riesgo (de PT-A2) | Control Clave (de PT-A3) | Diseno RC | Operacion RC | Riesgo Residual | Procedimiento Sugerido | Hallazgo Vinculado S1. FILAS PRE-LLENADAS (auto de PT-A2): Un fila por cada riesgo identificado S2. COLUMNAS DE CONTROL (auto de PT-A3): Controles evaluados enlazados a cada riesgo S3. PROCEDIMIENTOS (auto del Programa): Al crear el programa, las procedimientos se enlazan de vuelta a la matriz S4. HALLAZGOS VINCULADOS (auto): Cuando se crea un hallazgo en ejecucion, aparece en la fila correspondiente S5. RIESGO RESIDUAL (calculo automatico): RI × (1 \- efectividad del control) \= RR S6. VISION DE COBERTURA: Heatmap que muestra que areas tienen mayor riesgo residual 🤖 Asistencia de IA: El Agente Atlas sugiere controles adicionales no identificados para areas de TI segun COBIT/NIST El Agente Sherlock resalta riesgos de fraude que deberian tener procedimientos especificos El sistema calcula el Riesgo Residual automaticamente al capturar el resultado de la evaluacion del control Cuando se cierra la auditoria, la matriz actualiza el registro de riesgos del universo de auditoria ⬇️  Recibe datos de: PT-A2 (riesgos inherentes) PT-A3 (controles evaluados) ⬆️  Alimenta datos a: Programa de Auditoria (procedimientos por riesgo) Hallazgos (vinculacion de hallazgo a riesgo/control) Dashboard de Riesgo (alimenta el heatmap del CAE) Universo de auditoria (actualiza risk score de la entidad)  |

## **FASE B — EJECUCION**

|  PT-PROG Programa de Auditoria *El plan de trabajo de ejecucion — generado automaticamente basandose en los riesgos de la MRCI, el enfoque del Memo y las mejores practicas del Skill activo* PT MAESTRO 📝 Secciones del Papel: S1. PROCEDIMIENTOS AUTO-GENERADOS por area/riesgo (basados en PT-MRCI y enfoque definido) S2. Por cada procedimiento: objetivo, descripcion detallada, tipo (sustantivo/controles/analitico), tamano de muestra (calculado sobre ME), referencia al papel donde se documentara S3. ASIGNACION: auditor responsable (sugerida segun expertise en gestion de competencias) S4. HORAS ESTIMADAS: basadas en el tamano de muestra y complejidad S5. ESTADO: Pendiente / En proceso / Completado / Con excepcion S6. VINCULO AL PAPEL: cada procedimiento enlaza al PT donde quedara documentado S7. SECCION EDITABLE: el auditor puede agregar, modificar o eliminar procedimientos S8. VALIDACION DE COBERTURA: semaforo que indica si todos los riesgos significativos tienen al menos un procedimiento 🤖 Asistencia de IA: El Agente Scriptorium genera los procedimientos segun el tipo de riesgo, nivel de RD requerido y Skill activo (TI, Fraude, Financiero, Compliance) Los tamanos de muestra se calculan usando la formula estadistica de muestreo por atributos o MUS segun el tipo de prueba El sistema alerta cuando un riesgo significativo (NIA 315\) no tiene un procedimiento especifico asignado El Agente Atlas agrega procedimientos especificos COBIT/NIST para areas de TI identificadas ⬇️  Recibe datos de: PT-MRCI (riesgos y brechas de control) PT-MEMO (enfoque y materialidad) PT-A3 (Riesgo de Deteccion requerido) Skills del dominio activo ⬆️  Alimenta datos a: PT-B1 a PT-B9 (papeles de ejecucion por procedimiento) PT-MEMO (el programa es el primer documento de ejecucion) Dashboard del proyecto (avance de procedimientos)  |
| ----- |

|  PT-B1 Cuestionario de Evaluacion de Controles *Evaluacion detallada de controles por proceso — vinculado directamente a la MRCI* PT INTELIGENTE 📝 Secciones del Papel: S1. Proceso evaluado (vinculado a un area de la MRCI) S2. PREGUNTAS DE CONTROL (auto-generadas segun el proceso y el Skill activo) S3. Por pregunta: Si/No/Parcial, evidencia obtenida, observacion del auditor, tick mark S4. Conclusion por control: Efectivo / Con debilidades / Inefectivo S5. Vinculo a hallazgo cuando la respuesta revela una deficiencia S6. Referencia a evidencia adjunta 🤖 Asistencia de IA: El Agente Atlas genera las preguntas del cuestionario segun el proceso (compras, nomina, TI, etc.) y el framework aplicable (COSO, COBIT) Cuando se marca un control como Inefectivo, el sistema ofrece crear un hallazgo borrador con la observacion pre-cargada El resultado del cuestionario actualiza automaticamente la columna RC de la MRCI ⬇️  Recibe datos de: PT-PROG (procedimiento de evaluacion de controles) PT-MRCI (controles a evaluar) ⬆️  Alimenta datos a: PT-MRCI (actualiza columnas de control y RC) PT-A3 (evidencia de evaluacion de controles) Hallazgos (deficiencias pre-cargadas)  |
| ----- |

|  PT-B2 Papel de Procedimiento Sustantivo *Documentacion de procedimientos sustantivos — analisis, recalculos, verificaciones y pruebas de detalle* PT INTELIGENTE 📝 Secciones del Papel: S1. Procedimiento ejecutado (vinculado al PT-PROG) S2. Objetivo del procedimiento S3. POBLACION Y MUESTRA: total de la poblacion, tamano de muestra (de PT-PROG), metodo de seleccion S4. RESULTADOS: tabla de items revisados con columnas configurables (tick marks aplicables) S5. EXCEPCIONES IDENTIFICADAS: descripcion, impacto calculado, proyeccion a la poblacion S6. COMPARACION VS. MATERIALIDAD: impacto acumulado vs. UAE y MG S7. CONCLUSION: el procedimiento cumplió su objetivo? Hallazgo requerido? S8. VINCULO A HALLAZGO: si hay excepcion material, boton Crear Hallazgo pre-llena los campos 🤖 Asistencia de IA: Los datos del ERP cargados via Agente Vulcano se presentan directamente en la tabla de resultados para que el auditor marque con tick marks El sistema calcula automaticamente la proyeccion de errores a la poblacion y la compara contra la materialidad El Agente Scriptorium redacta la conclusion segun los resultados documentados ⬇️  Recibe datos de: PT-PROG (procedimiento y muestra asignada) PT-A4 (materialidad para comparacion) Datos del ERP (Agente Vulcano) PT-MRCI (riesgo/area que este papel cubre) ⬆️  Alimenta datos a: Hallazgos (excepcion material → hallazgo pre-llenado) PT-CIERRE (conclusion del proyecto consume las conclusiones de todos los PT-B) Informe (hallazgos del papel van al informe)  |
| ----- |

|  PT-B3 Guia de Entrevista \+ Papel de Entrevista *Documentacion profesional de entrevistas — desde la guia previa hasta el papel de trabajo post-entrevista* PT INTELIGENTE \+ Grabacion 📝 Secciones del Papel: PRE-ENTREVISTA: S1. Objetivo de la entrevista S2. Entrevistado: nombre, cargo, area S3. GUIA DE PREGUNTAS (auto-generada por IA segun objetivo y rol del entrevistado) POST-ENTREVISTA: S4. Transcripcion del audio (Whisper API — transcripcion automatica) S5. Identificacion de hablantes (Speaker Diarization) S6. COMPROMISOS Y DECLARACIONES CLAVE (extraidos automaticamente por IA) S7. | // ai-service/src/graph/paper-graph.service.ts @Injectable() export class PaperGraphService {   constructor(     private prisma: PrismaService,     private eventEmitter: EventEmitter2,     private scriptoriumAgent: ScriptoriumAgent,   ) {}   // Cuando un PT Inteligente cambia, propaga a sus dependientes   async onSectionUpdated(paperId: string, sectionKey: string, newValue: any) {     // 1\. Encontrar todos los papeles que dependen de esta seccion     const dependents \= await this.prisma.paperLink.findMany({       where: { sourceId: paperId, sourceField: sectionKey },       include: { target: true }     });     for (const link of dependents) {       // 2\. | El auditor completa PT-A1, PT-A2, PT-A3 y PT-A4.
